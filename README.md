# Мастерская игровых предметов

Продвинутый вариант ДЗ № 2

## Запуск

Нужны Node.js 20+ и npm. В папке проекта:

```sh
npm ci
npm run build
npm test
```

Forge устанавливается с зависимостями. Если он уже установлен отдельно, после npm ci можно выполнить команды напрямую:

```sh
forge build
forge test --force
```

Первый запуск требует интернета. Тесты работают локально.

## Правила

В игре есть дерево (id 1), руда (id 2) и мечи (id 3). Владелец игры выдаёт дерево и руду через issue. Нужно указать ненулевой адрес получателя и количество больше нуля. Мечи напрямую выдавать нельзя.

Из ресурсов игрок создаёт мечи через craft(n). На каждый меч уходит 3 дерева и 2 руды. После обновления до V2 появляется salvage(n): каждый разобранный меч возвращает 1 руду. Дерево не возвращается.

Игрок использует только свои предметы и получает результат себе. Количество должно быть больше нуля. Если предметов не хватает или получатель отказывается их принять, вся операция отменяется.

totalCrafted считает созданные мечи, а totalSalvaged считает разобранные. Разбор не уменьшает число созданных мечей, а переводы между игроками не меняют оба счётчика.

## Обновление

Игроки обращаются к игре через прокси. Он хранит данные и передаёт вызовы контракту с правилами игры. При обновлении V1 заменяется на V2, а прокси остаётся прежним.

Поэтому адрес игры, владелец, предметы игроков, разрешения на переводы и totalCrafted сохраняются. V2 добавляет счётчик totalSalvaged, который начинается с нуля. Перед обновлением OpenZeppelin Upgrades проверяет совместимость хранения данных с сохранённой V1. Эта проверка не отключена.

Владелец игры выдаёт ресурсы, а отдельный владелец ProxyAdmin отвечает за обновления. Повторно задать начальные настройки прокси нельзя. Напрямую инициализировать контракты V1 и V2 тоже нельзя.
